# Контракт API СИНАПС

`openapi.json` — генерируемый OpenAPI 3.1. Реестр `crates/api/src/contract.rs` одновременно регистрирует маршруты Axum и собирает схему из атрибутов обработчиков и Rust-типов. Команда экспорта не подключается к БД и не запускает HTTP-сервер.

```powershell
npm run api:generate
npm run api:check
npm run check
```

Первая команда обновляет OpenAPI, `apps/frontend/src/lib/generated/api.ts` и `endpoints.ts`. Вторая проверяет точное соответствие всех трёх файлов текущему серверу и завершает процесс с ошибкой при расхождении. Сгенерированные файлы следует сохранять вместе с изменениями исходников. В Windows перед изменениями серверных типов остановите запущенный `synapse-api.exe`, чтобы Cargo мог пересобрать исполняемый файл.

Работающий сервер отдаёт тот же документ по `GET /api/v1/openapi.json`. Это описание схем без данных пациентов, сессий или примеров с настоящими учётными данными. Cookie-сессия и маркер изменяющих запросов описаны в контракте; права проверяются сервером на каждом запросе.

Фронтенд вызывает именованные операции:

```typescript
const patient = await api('get_patient', { params: { id } });
const page = await api('list_patients_page', { query: { limit: 20 } });
await api('update_patient', { params: { id }, body: profile });
```

Параметры пути, query, тело и успешный результат выводятся из сгенерированного контракта. Произвольный путь, метод или указанный вызывающим кодом тип ответа не принимаются. Русские подписи статусов и типов событий остаются в интерфейсе; соответствие ключей серверным перечислениям проверяет TypeScript.

Общий транспорт сохраняет браузерные cookie, тайм-ауты и обработку ошибок. В Tauri он передаёт параметры отдельно в Rust-мост, преобразуя числовые query в строки; сессия остаётся в памяти Rust. Генерация не добавляет валидатор схем в мобильный пакет.

`api.contract-check.ts` проверяется компилятором и не вызывается приложением. Его отрицательные примеры должны отклоняться: отсутствующий UUID, неправильный тип лимита, неизвестная операция, неполное тело входа и неправильный тип ответа.

При запущенном локальном API с демо-данными:

```powershell
npm run test:contract
```

Проверка сравнивает живой документ с сохранённым, компилирует схемы и проверяет реальные ответы через Ajv, включая JSON/текстовые ошибки и 204 без тела. Создаваемые синтетические UUID записываются в `tmp/contract-api-fixtures.json` для последующей точечной очистки. CI проверяет актуальность генерации до сборки фронтенда и запускает проверку ответов после старта API.

Схемы описывают структуру и форматы данных. Бизнес-правила, ограничения доступа, нормализация, сроки приглашений и конкурентные изменения дополнены в [API.md](API.md) и проверяются сервером и интеграционными сценариями.

Инструменты: [utoipa-axum](https://docs.rs/utoipa-axum/0.2.0/utoipa_axum/), [openapi-typescript](https://openapi-ts.dev/), [Ajv](https://ajv.js.org/json-schema.html).
